# Explicit local exclusion adjudication

The Case-labeling checkbox records the current author's opinion. Another effective exclusion vote can still keep the Issue in local exclusion candidates. A compact Exclusion details button next to the personal checkbox opens a read-only modal. It separates the author's saved opinions, the canonical local projection, and the asynchronously queried Trail state; effective exclusion sources and current task decisions are expanded by default. Only a short known local/Trail mismatch appears inline.

A separate Exclusion decision dialog is available without a task URL when an active writable labeling task has exclusion evidence. It also covers pending tasks and equal-label/different-exclusion opinions. This reuses the existing full task adjudication: choose a valid source label, inspect its expected output/tags/evidence, choose Exclude or Do not exclude, enter a rationale, and explicitly confirm the full conclusion. It is not an exclusion-only record and does not modify the schema. Independent labels remain outside this task decision contract; another excluded source may retain the aggregate exclusion.

POST label-cases/{id}/adjudications accepts adjudication_scope=exclusion with confirm_full_label=true. Existing verified writer checks, active-task guards, all current source revision IDs and previous-resolution CAS remain. A successful operation appends the existing adjudication revision and resolution, preserving original heads/history. Source changes invalidate the result. Duplicate stale requests are rejected before another append. No GT update or Trail write occurs.

The modal snapshots source versions, keeps an independent bounded draft, locks pending submission, and preserves drafts on failures/close/locale changes. Refresh sources keeps rationale but clears old source choice and confirmation. Success refreshes only the current Issue projections; ordinary label drafts/images survive, and late responses do not navigate or alter another Issue.

Focused database/Node tests exercise pending and resolved disagreement, explicit confirmation, source/decision CAS, old source retention, read-only tasks, independent-source boundaries, duplicate calls, failures and navigation. Synthetic actual-frontend browser checks cover 1440px desktop and390/320px narrow screens with Chinese/English and representative light/dark themes. Real device/soft keyboard and signed-in production writes were not tested. cn32057309 was inspected read-only and not adjudicated by this task. Deployment evidence lives in reports/manual_exclusion_decision_20261023.


Issue adjudication uses compact source cards and directly visible original opinions, plus the complete returned Issue decision history (result, author, time and rationale). The current/stale decision is identified without hiding earlier records. Its editing section and fixed footer are separate; blocking task sources keep their original guard and task link. The first Escape closes an enhanced picker before a second Escape closes the dialog.

The exclusion overview now uses two compact summary panels, common primary filters and an expandable secondary filter area. Technical target paths stay in JSON/confirmation, not a large summary card. Desktop rows have aligned selection/Issue, compact colored state and two one-line reasons; complete reasons and provenance open in an independent scrollable dialog. Mobile rows remain cards. API states and writer eligibility are unchanged. Presentation groups shared by badges/totals/filters are: needs_exclusion (amber), reason_update (purple, changed + missing), synced (green, marker and nonempty reason agree), excluded (blue, marker true with no new local reason), not_excluded (neutral reconciliation), querying (neutral), unconfirmed (red). Legacy status URL values map to these groups. Historical-only rows remain read-only.

The summary panels use equal desktop columns; candidate counts and table headings/states are centered. Checkboxes and the selected-update toolbar are hidden during ordinary browsing. Batch update explicitly opens selection; Done selecting clears it. Scope changes reset selection mode, and read-only reconciliation never exposes the batch action. The update-type selector reuses the shared enhanced select, including Escape and bilingual options. Status patches retain row identity and active selection.

Case labeling also exposes Export Issues beside the existing gallery actions. It snapshots the same complete query/filter contract as the gallery and downloads a UTF-8 BOM CSV of every matching Issue ID across pages. The existing complete queue response is used; an incomplete response fails explicitly instead of silently exporting one page. Duplicate clicks are guarded, and exporting does not change the active gallery page or filters.

Initial Trail loading is independent of the shared Run registry, reviewer facets and overview. The essential dataset configuration resolves first, then the local candidate list paints with a small initial placeholder; a separate remote status read patches the existing rows. Run scope stays explicit even while its enhanced picker is loading. Late responses from an old page epoch, dataset/view or Run cannot apply or rewrite navigation, and current filters are persisted when the local response arrives. Remote failure preserves local rows and keeps writes disabled. The ordinary local view omits the redundant dataset/query-coverage text; the read-only historical reconciliation retains its source/coverage explanation.
