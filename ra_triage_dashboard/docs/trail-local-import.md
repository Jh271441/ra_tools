# Trail → 本地排除导入

问题排除页的「从 Trail 导入 / Import from Trail」打开后自动分批核对所选数据集，
列出 Trail 明确排除而本地未排除/无记录的 Issue。支持勾选最多 200 条，
也保留折叠的手动输入入口；预览后明确确认保存。不会自动导入，不修改 Trail、GT、
模型结果或任务分配，也不发送提醒。

## 接口

- `POST /api/trail-attribute-update/local-import-candidates`：
  `{ "baselines": "0508", "after": "" }`，每次扫描 100 个数据集成员，返回
  `next_cursor`、`scanned`、`total` 及差异项。扫描无写入，包含无本地标注的成员，
  不依赖历史排除快照。已有裁决或冲突的差异项仍可见，但 `can_import=false`。
  未完成或失败必须提示结果不完整，不能把缺失响应当作未排除。
- `POST /api/trail-attribute-update/local-import-preview`：
  `{ "issue_ids": ["cn12345678"], "baselines": ["0508"] }`。
  返回当前用户绑定的 `preview_id`、10 分钟有效期以及本地改动前后对比。
- `POST /api/trail-attribute-update/local-import-commit`：
  `{ "preview_id": "…", "confirm": true }`。
  重新读取 Trail，并验证本地来源未变；成功返回操作 ID、每条版本 ID、
  `imported_count`。相同预览重复提交返回已存结果，不重复追加。

两接口要求可信身份、writer/admin 权限及同源请求标记。预览仅查询；
远端写入开关不影响本地导入权限。远端必须明确为布尔 `true`，
缺失、false、数值 1 不能作为排除导入。批次任意一项校验失败则整体拒绝。

## 保存与冲突规则

保存为当前用户的新个人 Issue 标注，`author_source=trail_import`。
保留该用户已有分类、Tags、证据及图片，历史版本不改；没有个人分类时，
仅新增排除意见，分类仍待标注，不虚构 GT 或分类。

- 本地为空、Trail 有理由：采用 Trail 理由。
- Trail 为空、本地有理由：保留本地理由。
- 两边非空且不同：拒绝导入，先人工核对。
- 已有裁决、当前个人来源属于任务或被停用：拒绝导入，不绕过任务/裁决。
- 内容已经一致：不新增版本。

这是个人意见，不是全局裁决；其他用户的意见仍按既有聚合规则参与。
来源显示为「Trail 导入」，审计保存来源快照、操作者和新增版本 ID。
版本与审计在同一数据库事务中保存。

## 状态口径

本地与 Trail 均已排除且理由相同（包括两边理由均为空）显示「已同步」。
本地理由为空但 Trail 非空才显示「本地理由待补」。原始 API 枚举不变，
状态图、列表、筛选共享展示映射。历史来源仅确认远端排除时仍显示「已排除」，
不声称本地与远端一致。

## 发布与限制

PostgreSQL 需先执行迁移 `058_trail_local_imports.sql`；SQLite 初始化包含该表。
这是新增审计表，不回填或改写已有标注。发布须按项目迁移流程备份、演练、验证。
接口预览暂存内存，未提交预览在服务重启后失效；已成功提交的幂等结果持久保存。
Trail 没有跨系统事务，读取后发生的外部编辑不能被本地事务锁定。
扫描范围是所选数据集的全部本地成员，不是 Trail 的全部 Issue。扫描是分批当前读，
并非跨系统一致性快照；提交仍会重新核对，扫描后有变化时应重新预览或查找。
