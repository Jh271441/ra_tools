# 标注汇总中的 GT 更新占比

GT 信息直接放在 `/manual/labeling-summary` 的现有图表区，以百分比环图展示；没有独立菜单、页面或清单模式。旧链接中的 `gt_update` 前端参数忽略，刷新后回到普通标注汇总。图表不改变明细、筛选、分页或 GT。

统计口径是当前数据集、任务、人员及其他筛选内**已有标注的 Issue**，不是当前页，也不是所有未标注 Issue。数据直接复用 `gt_update_counts`；百分比环图和图例使用现有共享分析图表，颜色沿用主题变量。标题与相邻状态图保持同一基线，统计范围放在标题下方。

- **GT 待更新**：`label_gt_candidates` 与 GT 导出相同的全局规则。有有效 Issue 裁决时优先采用，否则各来源必须完整、有效且一致。有效三分类与当前 GT 不同或补齐缺失 GT。
- **需确认**：标注未齐、来源冲突或裁决过期。空分配和未标注 Issue 不进入分母。
- **与 GT 一致**：已标注 Issue 中其余无需更新的项；与上述两项互斥，共同构成分母。无数据时显示空环及“—”，不编造0%完成率。

任务筛选限定 Issue 范围，GT 资格仍判断全部来源。版本数据集仍限定当前目标成员。原有 GT 导出及后端兼容过滤能力保留；界面不再提供独立 GT 清单。查看只读本地数据，不写 GT、Trail、标签、任务进度或导出批次。

验收覆盖中英文、深浅主题与320/390/1440/1920响应式布局。`test_gt_queue_frontend_behavior.py` 检查实际JS中的百分比、零分母、无独立入口/模式、筛选与语言保留及离页响应保护。后端已有规则回归继续覆盖任务、冲突、分页、导出和只读边界。

## 原因聚类同步

`/manual/review-analysis` 使用同一个GT图表组件及布局。Model Review状态仍是Run复核状态；GT图统计当前筛选内Issue的共享标注结论，不从模型复核reason推导GT。模型Run、任务、人员、Tags、排除、讨论及其他条件全部应用后，再统计完整Issue范围，分页不改变占比。查询只读且不修改GT、复核、标注或进度；新GT字段不混入原有原因聚类和导出内容。
