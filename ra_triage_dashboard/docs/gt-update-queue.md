# GT 待更新清单

入口为「问题标注 → GT 待更新」，路由 `/manual/labeling-summary?gt_update=ready`；同一页面可切换全部标注、GT 待更新和需确认。复用标注汇总的任务、人员、结果、讨论、排除与 Issue 筛选和分页。链接、刷新和前进后退保留清单视图，重置只清除其他筛选。

- **GT 待更新**：使用 `label_gt_candidates` 与 GT 更新导出相同的全局规则。有有效 Issue 裁决时优先采用；否则各来源必须完整、有效且一致。有效三分类与当前 GT 不同，或补齐缺失 GT 时进入清单。
- **需确认**：来源冲突、已有部分提交但标注未齐备，或裁决已过期。纯空分配、未标注 Issue 和 GT 已一致条目不冒充待更新。
- **任务范围**：先按选中任务及其他筛选选定已提交 Issue，再基于这些 Issue 的全部来源判断 GT 资格、展示依据。某个任务已形成结论不会掩盖其他任务的冲突。版本数据集继续限定当前目标成员。
- **计数和明细**：队列筛选在分页之前应用；三个视图数量基于其他筛选后的同一范围。GT 对齐后，下次读取自动退出待更新清单。
- **安全边界**：查询只读本地已激活数据，不调用远程 Trail，不更新 GT、snapshot、标签、任务进度或导出批次。导出沿用现有权限、预览、冻结指纹及下载前重新校验；所选队列和其他筛选传入导出，不扩大范围。

界面复用共享单选、多选、按钮、清单、主题变量和最终手机覆盖层；新增文案支持中英文。浏览器响应式检查不能替代真机测试。

## 回归

`test_labeling_gt_queue.py` 使用隔离 SQLite 检查差异/缺失/一致 GT、任务与跨来源冲突、缺提交、有效及过期裁决、分页、筛选、导出、查看只读、GT 对齐后退出、空选择及权限门禁。
`test_labeling_version_membership.py` 验证版本目标成员与导出范围一致。
`test_gt_queue_frontend_behavior.py` 执行实际 JS，检查精简清单不绑定未挂载图表，语言切换、导航、重置、URL 和离页后的过期响应保护。
