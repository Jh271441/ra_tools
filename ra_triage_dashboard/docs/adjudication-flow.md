# Issue 标注与完整裁决（2026-10-24）

本文描述已于 2026-10-24 部署的完整裁决实现，应用版本 `18ace74`、前端缓存 `manual-triage-637`、PostgreSQL schema56。云端823项测试通过、5项跳过；备份恢复校验、隔离灰度和生产健康检查通过。

## 状态与范围

分类与是否排除分别展示状态和结果，不再用一个“待裁决”混合表达所有问题。

| 展示状态 | 含义 | 处理方式 |
|---|---|---|
| 待补齐 / Incomplete | 尚缺人员提交、有效分类或排除信息 | 补充个人标注，或由有权限的裁决人明确确认完整结果 |
| 有分歧 / Disagreement | 当前有效意见互相冲突 | 对照原始意见，采用其中一版或重新标注后裁决 |
| 待复核 / Needs recheck | 先前裁决依赖的来源已经变化 | 对照新来源重新确认；原裁决保留在历史中 |
| 已确认 / Confirmed | 当前有效意见一致，或存在有效裁决 | 展示当前结果及其形成原因；不代表 GT 已更新或任务全部提交 |

API、数据库及 URL 保留既有 `pending/resolved/conflict/stale` 枚举；分类筛选中的“有分歧 / 待复核”继续共用 `conflict` 查询。排除分歧单独展示，不用它改写分类状态。

联合复核的任务进度仍依赖原分配下的 `model_review_submitted` 与 `case_label_acknowledged`。完整 Issue 裁决可以确认尚有人员未提交的 Issue，但不代替这些人的提交，不增加任务完成数。

## 完整裁决包含什么

每次保存追加一条不可覆盖的 Issue 裁决，包含：

- 最终三分类、Tags、证据缺口、标注依据、是否排除，以及最多四张证据图片。
- 独立的裁决人补充依据（选填）、裁决人身份和时间。留空按空值保存，不自动复制原作者依据。
- 若采用现有标注，记录精确的标注版本 ID、原作者、原文与原始结果快照，以及修改了哪些字段。
- 当前所有来源的版本指纹与被替代裁决 ID，供并发校验和后续失效判断。

**是否排除必须是明确的 true 或 false。** 页面要求裁决人再次确认该选择；修改排除选择或确认新来源后，需要重新勾选确认。普通个人标注和裁决草稿相互独立，退出裁决后恢复个人未提交内容与图片。

## 操作流程

1. 点击 Issue 标题旁的状态按钮，或标注历史入口，打开“标注与裁决”。顶部分别说明分类和排除结果；下方展示每人的当前标注，历史标注和裁决记录可展开。
2. 在任意当前或历史版本中点击“采用此标注”，或者选择“重新标注并裁决”。两者都进入原页面的完整标注表单，明确显示“裁决模式”，复用现有下拉、Tags、媒体和截图功能。
3. 采纳时可展开原作者依据，允许修改最终结果；裁决人可选填补充依据。原记录不会被修改。证据缺口按选定版本保留并只读展示，遵循现有主表单能力。
4. 确认分类、标签、依据、截图与是否排除，提交完整裁决。保存中阻止重复提交和切换 Case；权限、数据集及来源版本在服务端复验。
5. 若来源或裁决已变化，返回 409 并保留草稿。选择“对照来源”，刷新并查看新意见，再明确点击“已对照，保留草稿继续裁决”，才更新草稿的来源指纹。仅关闭弹窗不会接受新来源；语言切换、再次刷新均保留该复核入口。
6. 保存后刷新当前结果。未提交的个人草稿继续保留，不会被裁决覆盖。

## 结果优先级与兼容

| 数据 | 当前优先级 |
|---|---|
| Issue 分类 | 有效 Issue 裁决优先；否则按现有任务结果与个人当前意见求一致，不按多数票或更新时间选赢家 |
| Issue 排除 | 有效完整 Issue 裁决优先，包括显式不排除；否则按原有任务裁决及当前个人意见合并，任一有效 true 暂按排除生效 |
| Issue Tags | 有效完整 Issue 裁决的 Tags 优先；否则合并有效任务结果或个人当前意见 |
| 标注与图片历史 | 保留原作者、全部版本、原始依据；采纳引用精确版本，不能引用别的 Issue 或别的版本的图片 |
| 任务进度 | 保持原任务提交规则；Issue 裁决不替人提交 |
| GT 与 Trail | 保持独立事实，裁决保存不写入任何外部系统 |

旧的 Issue 裁决只有三分类，`full_result_json` 为 NULL。它仍可确认分类，但“是否排除”表示**未裁决**，不能解释为 false，也不能覆盖原有排除意见或 Tags。原任务裁决 API 保留兼容；新的页面统一使用完整 Issue 裁决。

来源有新版本，即使只修改依据或 Tags，也会使绑定旧指纹的裁决失效。失效的完整裁决不再覆盖当前排除和 Tags，页面提示待复核。暂不拆分字段级指纹。

## GT、Trail 与理由边界

GT 候选可以引用有效裁决，但更新 GT 仍需独立预览和确认。Trail 当前状态独立展示；本地排除裁决只改变本地结论，不自动写 Trail，也不自动取消远端已存在的排除。

排除发布候选保留裁决 ID；理由优先采用最终标注依据，缺失时回退到裁决人补充依据，继续使用已有的预览、明确确认、审计、幂等和读回流程。原始 Case 排除理由缺失时，仅允许沿既有规则恢复该精确迁移版本自己的旧备注，不能借用其他人的文本。现有 Trail writer 只支持写 true 与理由更新，远端撤销不在此次范围内。

- `POST /api/labeling/issues/{issue_id}/decisions`：保留旧 JSON 合约；新完整结果显式传 `full_result: true`、布尔 `is_excluded`、`label_rationale`、裁决 `rationale`、`adopted_revision_id`、`retained_attachment_ids`、来源指纹和此前裁决 ID。
