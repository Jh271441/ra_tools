# 每日数据 / 每日任务

入口 `/daily-cron`；配置 `DASHBOARD_BASE_PATH=/manual` 时公开入口为
`/manual/daily-cron`。中文入口统一命名为“每日任务”，放在“每日数据”可折叠导航组内；
两条独立任务显示为“推理回刷”和“平台与媒体”，沿用工作台的主题、字体和响应式布局。

`GET /api/daily-cron` 在工作线程中并行读取同机独立监控服务的三个固定只读接口：
`127.0.0.1:8791/api/overview`、`/api/history`、`/api/manual-sidecar`。
各请求限时 2 秒、响应上限 2 MB，禁用代理和重定向；5 秒 single-flight 缓存。
单个源不可用只降级对应区域，不隐藏其他源，不导入或执行被监控脚本。
只投影状态、数量和案例 ID，不透传原始命令、异常正文、日志或内部路径。

页面每 30 秒更新，隐藏标签页暂停请求；离开此路由清理定时器并取消请求。
手动刷新和顶部刷新仅更新本页，旧请求不会覆盖重新进入后的状态。
主流程分别展示最终回执和最近调度退出记录；恢复后完成时仍保留之前的失败退出记录。
阶段进度含失败项，不作为全链路成功依据。无数据、缺失、过期、不可用均明确标识。
历史按实际观测着色，无观测保持灰色。

按版本增量主视图在累计卡片下展示“每轮增量”：07:00、19:00 CST时段，
按版本分行展示首次发现ID、旧缺源案例补齐入队、回刷完成、目标入库及移出。
发现/补齐来源于只读队列事件；目标变化来源于平台不可变导入回执，重放不重复计数。
回刷/入库按实际完成时段统计，跨轮待办计入完成所在时段，几列不可相加。
这些是时段活动量，不宣称严格绑定同一扫描队列的全链路完成率。

只读取切换12小时调度之后的记录，保留最近14轮的展示；不删除底层历史。
control中的 `discovery_history_started_at` 固定历史起点，避免后续配置更新时间
清空展示。SQLite以mode=ro、query_only读取，查询设执行时间和数量上限；
单次最多读取50000条相关事件、5000条平台回执。缺记录、超限或读取失败显示不可用，
不伪造全零且不隐藏累计进度。此适配器不调用Trail、不触发采集或模型执行。
窄屏表格在本地容器滚动，中英文/主题沿用共享组件；历史每日任务隐藏该表。

媒体区将“日更已启用”和监控服务现有的“历史回溯媒体”分开显示。
原始 Orion 失败数保留，重试/本地修复结果以媒体最终验证为准；
历史数量不代表当天新增 Run 数。旁路不影响主流程结果。

本功能不变更调度、旁路、数据库 schema、身份校验或写入开关。
独立 Cron Observatory 8791 保留运行；新页面依赖它提供采集数据。

当前主视图为 Airflow Graph 模式的双任务运行图；静态规则图放在各卡片“!”中。
参照来源与交互映射见 [公开模式](daily-cron-ui-patterns.md)。
适配器另读取服务端配置 RA 根目录内的旁路心跳、按天导入/分配与媒体发布回执，
按完整Run冻结成员去重计数，不执行控制器、不读取视频或原始bag。
完整替换清单优先于旧部分Run；无证据的重试/本地阶段保留未知。
