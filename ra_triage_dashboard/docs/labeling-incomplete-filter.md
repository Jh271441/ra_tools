# 问题标注：未标注与待补齐分开筛选

“待补齐”原先使用 `status=pending`，同时选出未提交的 Issue 和已有提交但结论未齐的 Issue。GT 图只统计已有提交的 Issue，因此图中的需确认数量不能通过旧下拉准确定位。

结果状态沿用共享多选组件，区分：

- 未标注（`unannotated`）：当前查询范围没有标注提交或裁决；空分配也属于此项。
- 已提交 · 待补齐（`incomplete`）：存在提交，但聚合状态仍为 pending，包括任务成员未交齐、历史空结论。空结论不等于未提交。
- 已确认（`resolved`）：保持原有规则。
- 有分歧 / 待复核（`conflict`）：保持原有冲突和过期裁决规则。

这是查询分类，不改变数据库状态、裁决优先级、任务进度、历史记录或 GT。任务筛选仍使用对应任务范围；全局范围仍按所有来源判断。GT 候选继续使用独立的全局资格规则，不能用某个任务的一致结论覆盖其他来源。

后端旧 `pending` 保留“未标注 + 待补齐”的兼容语义；问题标注的旧链接在前端显式展开为这两个选项。标注汇总本来只展示有提交的明细，其旧 pending 链接恢复为 incomplete；前往问题标注时保留这个精确筛选。支持多选并集，与数据集、任务、人员、搜索等条件取交集，先筛选再分页；详情队列、Issue 导出、聚类与 GT 导出预览使用同一查询规则。

无需新增页面或 GT 清单；GT 环图保持原有展示布局。新增文案提供中英文，使用现有移动端下拉与触控规则。
