# Manual 内网链路与视频带宽竞争排查

诊断基线：`f8e2a483` / cache764。优化资源版本：cache765。
仅涉及 Manual Workbench。

## 同一次真实浏览器请求

在用户已登录的 macOS Chrome 中，通过原生 DevTools 读取已有慢请求，未导出 Cookie、HAR 或登录凭据。

Chrome 的 ZeroOmega 规则显示公司域名直接连接。秒级延迟主要位于应用中间件处理计时之外；该样本不支持“Discussion 数据库查询花了两秒”的解释。应用计时不覆盖请求进入应用前的服务调度、网关、SSO、VPN、TCP 传输等阶段，不能据此精确认定其中某一跳有问题。

服务端 loopback 同 Issue 对照：空闲 5 次中位数 5.2 ms；同时进行两条各 1 MiB 的有限视频 Range 读取时，8 次中位数 7.1 ms，最大 13.2 ms。两条媒体请求均为 206。该对照没有经过浏览器共享的 HTTP/2 连接和 VPN/网关，不代表用户端网络状况，也不能排除其他时段的服务阻塞。

此前 Mac 到内网入口的静态资源只读采样存在波动，但未复现秒级 Discussion 延迟；匿名 API 返回的是 SSO 302，不作为已登录接口性能数据。不改变代理、DNS、网关注册或认证策略。

## 消除额外等待和视频竞争

- 任务分配首次加载在 Run 目录完成前启动，任务列表与 Run/账号目录并行。URL 中指定的任务明细也不等待这些目录。账号未就绪时沿用共享下拉的禁用状态，已有负责人不误标为“已移除”。目录返回后原位更新选项，保留当前选择及明细行。
- Discussion 显示前暂停可见的 Workbench 视频播放器，取消其在途分片，并在弹窗打开期间保持挂起。关闭后只恢复仍连接且可见的原播放器；仍需用户明确点击播放，不自动播放。评论继续实时 GET，不引入陈旧评论缓存或更改提交确认机制。
- 暂停的 MSE 播放器只加载目标 GOP 和解码所需的后一个 GOP，去掉额外的前一个 GOP 预取；实际后退时按需获取。暂停时后一个片段使用低请求优先级提示。目标画面、原始视频质量、播放状态、范围校验和原生回退保持原契约；优先级是浏览器提示，不保证网关采用。

## 验证边界

- 实际 JS 行为检查覆盖：目录未返回时列表/明细可见、过期列表响应隔离、目录失败、延迟目录不重建明细行、目标与后续分片、实际后退按需加载、讨论 GET 前暂停、关闭后不恢复已移除/隐藏播放器。
- 原版本运行新增播放器回归检查会失败：暂停后下载目标、后一个和前一个 GOP；候选版本只下载前两项，实际后退仍按需请求原片段。原有视频生命周期检查、7 项任务链接/加载检查和 76 项前端契约检查通过。
- 独立 Chromium 合成只读页面覆盖 320/390/1440px × 中英文 × 深浅主题，共 12 组：辅助请求持续阻塞时主内容可见、共享下拉禁用/恢复、选择保持、Escape、语言切换、弹窗边界及关闭恢复。没有真实手机、软键盘、Safari/iOS 验收。
- 发布使用统一部署器的精确 SHA 全套测试、隔离灰度与生产 PostgreSQL/身份/写权限检查。具体发布与线上复测结果以 release receipt 和当前交接记录为准。

这些修改减少链路往返等待和媒体带宽占用，不等同于修复内网传输链路。不能把合成页面的改善当作已登录生产端到端的稳定耗时或 p95。
