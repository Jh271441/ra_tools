# Manual 看板加载性能复核（2026-11-05）

用户现象：首次打开、刷新和多个页面的加载都有延迟，对网络波动比较敏感。
本次基线为 `27805f9b` / cache763；本次资源版本为 cache764。

## 发现与修改

### 网络传输

- HTML、配置、列表和详情 JSON 原先均以 identity 返回。增加仅针对完整 HTML/JSON GET 响应的 gzip，保留缓存、身份和安全响应头。
- 视频、图片、Range、下载、SSE 和分块流继续使用各自响应方式；写请求和小响应不进入新增压缩逻辑。
- 首屏原先请求 21 个样式文件。服务器按 `index.html` 的 `stylesheetPaths` 顺序构建 `/static/app-bundle.css`，启动时生成 identity/gzip 两种表示与各自 ETag。最终覆盖层仍为 `css/mobile.css`。
- 样式请求从 21 次降为 1 次；压缩后正文合计由 125,352 bytes 降为 113,197 bytes。原组件文件继续可访问。

压缩前线上响应的正文大小及同一正文的 gzip 大小：

| 响应 | 原正文 bytes | gzip bytes |
| --- | ---: | ---: |
| 页面 HTML | 297,519 | 53,865 |
| dashboard-config | 80,391 | 12,550 |
| model-runs（0508） | 152,455 | 26,059 |
| cases（0508，20 条） | 48,418 | 4,514 |
| Issue core（不含媒体） | 88,121 | 12,124 |

表中 gzip 数值用于比较传输量，业务数据更新会改变实际响应大小。

### 加载顺序

- 系统状态、用户管理和标注上传的可见数据与 Run 目录并行加载。Run 目录继续初始化，支持后续 SPA 导航。
- Review/原因聚类页面按需读取复核人和任务负责人筛选；从其他页面进入时补齐。
- 身份与权限就绪后，@ 人员目录在后台加载。
- 原因聚类的结果查询与可选任务筛选并行，URL 中已选任务保持有效。
- 为概览、人员目录和分析任务选项补充响应顺序/上下文校验，延迟到达的旧请求不能覆盖新选择。

### 数据库读取

- 分页总数与 ID 查询只连接筛选条件用到的表。普通列表总数不再逐条解析 Review 投影。
- 无派生筛选的负责人统计直接读取完整 Issue ID 集合；派生标注状态、GT 关系、排除和标签筛选继续使用既有投影流程。
- 内部完整范围读取保留超过 5000 条的成员；公开 ID 查询仍限制 5000 条，公开分页限制保持原契约。
- 概览的总数、Review 状态、模型覆盖、错误和已复核错误在一次投影中聚合。
- 最新 Review 和多人 Review 的关联显式携带 Issue 条件，帮助 PostgreSQL 收窄连接。

### 回归验证

- 新增响应压缩测试直接检查 ASGI 正文字节、协商、私有缓存策略、媒体/流/下载/Range、HEAD 和小响应。
- 样式资源测试核对完整拼接结果、移动层顺序、压缩、ETag、304 和 HEAD；现有脚本资源测试继续执行。
- 数据库测试核对组合筛选的总数/当前页/ID 一致性、普通计数的查询开销和超过 5000 条的内部统计范围。
- 延迟响应测试覆盖身份不等待人员目录、旧概览不覆盖新范围、旧任务选项不覆盖新 Run，以及既有导航与保存队列行为。
- 浏览器阻塞可选请求直至主内容显示：4 个页面 × 320/390/1440px × 中英文 × 深浅主题，共 48 组。检查布局边界、共享下拉复用、Escape、语言切换、刷新和 SPA 进入 Review 后的筛选初始化。
- Cron 继续覆盖同样 12 种宽度/语言/主题组合，检查配置未返回时可显示图表、版本选择与 URL 保留。
- 这是桌面 Chromium 的响应式验证，未执行真实手机、软键盘或其他浏览器测试；截图为合成数据场景。
- 发布由统一部署器执行精确 SHA 的完整 pytest、隔离灰度及生产健康检查，结果记录在发布 receipt。

### 生产发布后的只读复核

2026-11-05 19:18 CST，在云端 loopback 使用与基线相同的方法：3 轮，每轮最多 2 个并发只读请求。
以下为 HTTP 中位数，不包含公网、SSO 和浏览器渲染；这些样本不能用于声称 p95。

| 接口（0508） | 优化前 ms | 优化后 ms |
| --- | ---: | ---: |
| 图库列表，20 条，含缩略图 | 827.9 | 96.3 |
| 负责人筛选 | 1493.4 | 30.8 |
| 复核人筛选 | 862.4 | 474.6 |
| 概览 | 1507.2 | 842.6 |
| 配置 | 134.1 | 222.4 |
| Run 目录 | 182.2 | 205.9 |
| Issue core，不含媒体 | 41.5 | 61.9 |

本轮并非所有接口都更快；配置、Run 目录和详情仍有读取及序列化成本。
实际 gzip 正文：HTML 53,927 bytes、配置 12,486 bytes、Run 目录 26,058 bytes、图库列表 4,513 bytes。
样式 bundle 的 identity/gzip、根路径与 `/manual` 子路径、HEAD、条件请求均已复核。
线上复核另发现 Starlette 的 304 允许列表要求小写头名称，补充 `Headers` 归一化，
并以先失败再通过的回归检查覆盖脚本及样式的 ETag、Cache-Control、Vary 保留。

已登录的旧 cache763 页面曾验证正常显示；发布后浏览器重连多次超时，
因此不把本地浏览器检查写成新版本已登录生产交互验收。

## 仍需区分的延迟

- 大范围且带 Run 的概览仍有约 1.56 秒数据库成本，主要来自有效 Review 选择；业务页面的可见数据按上述依赖关系加载。
- daily-cron 冷快照刷新基线曾测得约 2.76 秒，发布后首次刷新为 6.51 秒，缓存命中为十几毫秒；本次没有改动这条既有采集/快照刷新路径。
- 公网/SSO/VPN 的实际 RTT、丢包和可用带宽仍影响加载；合并资源和移除可选串行依赖减少了受影响的次数。
