# 视觉模型判定 Prompt v2.0

## 任务描述
对一次 stuck 检出（系统在时刻 t 触发了远程协助）做**后处理标注**，判断该次触发属于以下哪一类：**正确触发**、**误触发**、**无需协助**。

## 背景
自动驾驶车辆有 stuck 检测功能：检测到无法通过或卡在原地（如施工、窄路、不合理让行等）时会触发人工远程协助。该检测可能存在误触发或场景在触发后自行解除，需要对每次检出做后处理标注（正确触发 / 误触发 / 无需协助），用于检测模型迭代训练。

## 标注定义

### 正确触发
确实处于卡住/无法通过场景，长时间无法移动且**无自动放行机制**。包括但不限于：
- 施工、窄路、路中固定障碍（地锁、锥桶、落石等）；
- **违停/故障车占道且车内无人**，自车长时间静止且未鸣笛/nudge 或尝试绕行；
- 对向占道、逆行或双车对顶导致无法通过；
- 行人/非机动车长时间占道不动且无避让意图、无自动放行预期；
- 本可绕行但自车长时间未尝试绕行而一直等待（不合理等待）。

**施工区域识别**：若画面出现锥桶/围挡/临时隔离带/施工车辆/临时导流，导致主约束对象所在区域被封闭或可通行空间极小；且主约束对象 `yielding_object_id` 对应的车辆/物体确实位于该封闭区域内，同时自车 speed 长时间接近 0、无鸣笛/nudge 或绕行迹象，倾向正确触发。

**判定要点**：障碍是否可预期在短时间内移开？若不可（违停无人、故障车无人、固定物等）且自车未 nudge/绕行，倾向正确触发。

**基于物理时序的判定证据**：
- 结合「车辆物理时序与协助信号分析」中的 `近静止持续时间`：若该时间长（例如接近 20s 甚至满格 25s），并且车速极低（均速 < 0.1m/s），主约束物体在整个时间窗口内持续存在且未发生状态改变，同时画面证据确认为非排队、非红绿灯场景，倾向判定为**正确触发**。

### 误触发
实际并未卡住，系统错误触发。包括但不限于：
- **排队等灯**：前方车辆为车道内正常排队，画面可见远处红绿灯、前方有连续车流跟随，非路侧单独停放；
- 路口礼让/等待转弯或汇入、斑马线前礼让行人；
- 礼让行人/车辆、正常减速停车；学校/医院等特殊区域减速让行；
- **停车场/小区出口等待道闸、栏杆抬杆**（车牌识别或取卡后会自动放行）而短暂停车；
- 前方为**正常排队缓行**（红绿灯、拥堵），前方车辆为动态排队车、非违停/故障车；
- 若在多数时间点里 `speed` 明显较高（例如 >3m/s）仍触发 stuck，通常更符合"误触发"（车辆在正常行驶/跟车通过或接近通过）；
- 临时靠边上下客等合理短暂等待。

**判定要点**：
1. **是否有自动放行预期？** 红绿灯变绿、道闸抬杆、行人过完、排队前进等，倾向误触发；
2. **前方车辆特征**：若前方车辆（yielding_object_id）在车道内、有连续车流跟随、远处可见红绿灯/路口，属于正常排队等灯，**无论等待多久都是误触发**；
3. **路侧 vs 车道内**：若主约束车辆位于车道中央（非路侧停放）、前方有其他车辆排队，则属于正常排队，**不得因"speed=0持续时间长"而判正确触发**。

**基于物理时序的判定证据**：
- 结合「车辆物理时序与协助信号分析」中的 `车速演化`：若自车在触发前后的时间窗口内有较高的速度（例如触发前5s均速 `speed_pre_avg` 明显大于 0.5m/s，或规划轨迹均速较高），说明自车处于正常跟车或行驶过程中，倾向判定为**误触发**。

### 无需协助
触发 RA 前确实发生了 stuck 场景（如单车道被**违停/故障车占道**卡住 20s、施工路段被封闭），但在触发 RA 后，约束场景自行解除（如违停车突然驶离、施工临时放行），自车可以正常通行，**实际上不需要人工介入协助**。

**判定要点**：
- **排除等红灯场景**：若前方车辆为车道内正常排队（有连续车流、远处红绿灯），即使触发后绿灯放行前车驶离，也属**误触发**而非无需协助；
- **确属 stuck 场景**：前序时间窗口（t 之前）显示真正的 stuck 特征（路侧违停/故障车占道、施工围挡、固定障碍等），而非正常排队等灯；
- **触发后解除**：后续时间窗口（t 之后）显示约束解除（障碍物离开、speed 恢复）；
- **与"误触发"的核心区别**：误触发是"等红灯/道闸等正常等待被误判"，无需协助是"真有违停/施工等 stuck 但运气好自行解除了"。

**基于物理时序的判定证据**：
- 结合「车辆物理时序与协助信号分析」中的 `让行特征` 与 `车速演化`：若让行状态发生了 `Yielding→Free` 自行解除的变化（即 `yield_status_change` 标识为真），同时触发后10s的最大车速 `speed_post_max` 明显升高（例如大于 2.0m/s），说明在触发后障碍物自行离开或自车成功绕行，倾向判定为**无需协助**。

### 置信度分级标准（必须遵循）
- **高置信度 (0.8-1.0)**：证据非常明确，且至少同时满足（画面证据或 yielding 证据）与（速度/自车运动证据）两类一致。
  - **误触发高置信度**：画面清晰可见远处红绿灯、前方连续车流排队、自车随车流缓慢前行或等待；
  - **正确触发高置信度**：画面明确显示路侧违停/故障无人（无连续车流、单独停放）/施工围挡/固定障碍，且自车 speed 长时间接近 0、无绕行迹象；
  - **高置信度误触发**：speed 在多数时间点明显较高（例如 >3m/s）仍触发 stuck。
- **中等置信度 (0.6-0.8)**：证据较明确，但主要依赖单一维度或存在轻微不确定（例如只有 yielding+速度趋势，但画面对障碍类别识别略模糊）。
- **低置信度 (0.0-0.6)**：证据不足、冲突明显，或关键证据缺失导致无法可靠结论。

### 易混辨析
- **红绿灯排队 vs 路侧违停**：关键看**前方是否有连续车流** and **远处是否有红绿灯/路口**。
  - 若 yielding_object_id 指向的车辆在**车道中央**、前方有连续车辆排队、画面远处可见红绿灯或路口 → **正常等灯，属误触发**；
  - 若该车在**路侧单独停放**、前方无其他车辆排队、无可见红绿灯 → **违停/故障，属正确触发**；
  - 画面过暗/模糊无法确认时 → 选择置信度最低 of 合理分类（低置信度）。
- 仅「前方静止/慢行车辆 + 减速至 0」不足以判误触发——需结合画面判断该车是**违停/故障无人**还是**正常排队/临时停车**；违停无人且自车未 nudge 应判正确触发。

### 重要提示
- **红绿灯排队场景优先级**：若画面显示前方车辆为车道内正常排队（有连续车流、远处红绿灯/路口），即使 speed=0 持续较长时间，也属**误触发**（合理等待），**不得**仅因"等待时间长"而判正确触发或无需协助。
- **路侧违停判定**：只有当 yielding_object_id 指向的车辆**单独停放于路侧**、前方无连续车流、无红绿灯/路口可见时，才可判为违停/故障导致的正确触发。
- **兜底原则**：无法从画面明确区分"正常排队"vs"路侧违停"时，选择置信度最低的合理分类，并在 reason 中说明证据不足。

### 判定对象
必须以 **yielding 与 yielding_object_id 所指的那一辆车** 为准，看该车是否在车道内、是否紧跟车流。**不得以画面中远处其他车辆或车流是否移动** 作为「动态排队」的依据；若数据里 yielding 为「前方静止车辆」且同一 object_id 持续多秒，则该车即为静止约束车，应看该车在画面中的位置——若为路侧单独停放、非车道内排队，判正确触发。

### 建议推理流程
1. 先用时间窗口数据判断“自车是否长期被卡住”：重点看 speed 是否长期接近 0、acc/gear 是否显示仍在尝试前进但无法摆脱，并确认 `yielding_object_id` 在多点是否稳定。
2. 再按视觉输入时间轴和时间窗口表逐行对齐：若该行「图」列有相机图号，优先结合对应相机图核对障碍物、信号灯、车道与行人车辆细节；若同时有 BEV 图号，再结合 BEV 判断俯视空间关系、规划路径和连续运动趋势。
3. 若视觉变化不明显，回到时间窗口数据与 `yielding_object_id` 的持续一致性，不要只凭单帧外观下结论。
4. 最后综合画面证据、BEV/轨迹证据、速度与自车运动证据，输出 `label`、`reason` 与 `confidence`；证据足够一致才给高置信度。

## 输出要求
请**仅**输出一行合法 JSON，并确保输出内容不包含任何换行；不要使用 markdown 代码块或其它解释。注意：`label` 只能取三者之一（正确触发、误触发、无需协助），不要写成带斜杠的整串。输出格式示例（单行）：
{"label":"正确触发","reason":"示例：违停占道+施工围挡，speed≈0持续，无绕行迹象","confidence":0.90}
{"label":"误触发","reason":"示例：红绿灯排队/道闸自动放行，speed正常，无stuck证据","confidence":0.85}
{"label":"无需协助","reason":"示例：t前stuck证据充分，t后约束解除，前车驶离","confidence":0.80}

- `label`：只能取「正确触发」或「误触发」或「无需协助」
- `reason`：必须包含以下信息（简述即可）：
  1) 主约束对象：引用 `yielding_object_id`（说明其在车道内/是否紧跟车流/是否为路侧静止等）；
  2) 关键画面线索：引用至少 1 条可核对证据（例如红绿灯排队/道闸抬杆/锥桶围挡/施工车辆/违停无人特征），并注明图号与 t(s)（如"t=-2.0s 对应图3"）；
  3) 速度/自车运动证据：说明 speed/acc/gear 的趋势（例如 speed 长时间≈0、acc≈0、无绕行迹象），并解释为什么支持该 `label`。
- `confidence`：按"置信度分级标准"给出 0~1 的数值
